# Інтеграція «Щиро» з Hub

Hub — головна система для оплат, тарифів і підписок. Бот «Щиро» виконує
рішення про доступ, які приходять із Hub. Є два механізми; основний — перший.

| Механізм | Напрям | Що потрібно в «Щиро» | Стан |
|---|---|---|---|
| **Push: Hub керує списком доступу бота** (ТЗ інтеграції) | Hub → `Щиро /api/v1/hub/*` | роутер `admin/routers/hub_routes.py`, `HUB_API_SECRET` | реалізовано з обох боків |
| Pull: бот питає право в Hub на кожне повідомлення | Щиро → `Hub /api/v1/access` | `bot/core/hub_access.py` (файл поруч), API-ключ зовнішнього бота | доступно як доповнення |

Обидва механізми спираються на одне й те саме право в Hub: ресурс
`shchyro.access` (розділ «Цифрові продукти»), який входить у тарифи. Право є,
якщо:

1. у людини є ручне право в Hub (подарунок, тест, перехідний імпорт), або
2. активна підписка Hub на тариф із правом `shchyro.access`, або
3. активна підписка ZenEdu і в ресурсу увімкнено «Доступ усім активним
   підпискам ZenEdu» (перехідний режим, повторює нинішню щоденну вивантажку).

## 1. Push-модель: як працює

```
оплата / підписка / скасування у Hub
        │
        ▼
 тік щохвилини (/api/cron/tick → shchyroPushChanges)
   порівнює «хто має право зараз» зі знімком «кому Hub уже відкрив бота»
   нові → POST /api/v1/hub/access/grant
   зниклі → POST /api/v1/hub/access/revoke
        │
 щодня о 04:00 (/api/cron/daily → shchyroFullSync)
   POST /api/v1/hub/access/sync з повним списком: «Щиро» вмикає всіх зі списку
   і вимикає решту, крім адміністраторів і доданих вручну в його панелі
        │
        ▼
 access_list у SQLite «Щиро» → кеш бота 5 с → is_allowed(user_id)
```

Код: `src/lib/shchyro.ts`. Дії сторінки «Боти й меню»: `src/lib/actions.ts`
(`saveShchyroSettings`, `shchyroSyncNow`, `shchyroCheck`, `shchyroImport`).

### Де це в Hub

Розділ **Продукти → Бот «Щиро»** (`/shchyro`), чотири вкладки:

| Вкладка | Що там |
|---|---|
| Огляд | хто має право (тариф / вручну / ZenEdu), скільки відкрито в боті, клієнтки, активність, токени, тарифи з доступом до «Щиро», стан підключення |
| Люди | всі, хто писав боту: доступ у боті, право в Hub, розбіжності, повідомлення, картка пам'яті, посилання на картку в Hub і в панелі «Щиро» |
| Доступ | перемикач автоматики, ресурс, звірка (перевірити / застосувати), зв'язок, імпорт нинішніх доступів, список тих, хто має право, швидка видача за Telegram ID |
| Аналітика | звіт агента «Щиро» в Hub, кнопка «Оновити звіт», історія запусків, завантаження .md |

У картці людини (`/people/[id]`) є блок «Бот „Щиро“»: право в Hub і доступ у
боті, картка пам'яті бота, останні репліки, кнопка «Відкрити „Щиро“» на N днів
і повідомлення від імені бота.

Логіка видачі доступу та сама, що для каналів: **тариф → підписка → право →
бот**. Ресурс `shchyro.access` додається до тарифу в офферах; активна підписка
дає право, завершення підписки його закриває, Hub передає зміну боту.

### Єдине правило доступу (24 години грейсу)

Доступ до каналів, «Щиро» і кабінету дає підписка, поки вона активна, і ще
`access.graceHours` (Налаштування → Оплати, типово 24) після кінця оплаченого
періоду, якщо підписку скасовано або списання не пройшло. За цей час людина
може поновити оплату, і все повернеться само. Пауза закриває доступ одразу.
Після грейсу: канал виключає (з можливістю повернутись), «Щиро» отримує revoke,
кабінет переходить у стан «доступ завершено» з оффером. Повторні списання при
невдачі лишаються за графіком 1, 3, 5 днів, але без доступу після грейсу.
Код: `src/lib/access-rule.ts`; застосовано в `telegram-access.ts`,
`access.ts` (pull), `shchyro.ts` (push) і `onboarding.ts` (кабінет).
Підписки ZenEdu це правило не чіпає: ними керує ZenEdu до завершення переїзду.

### Запобіжник

Уся автоматика працює лише з увімкненим перемикачем **«Автоматика доступу
„Щиро“ увімкнена»** на вкладці «Доступ» (settings `shchyro.push_enabled`).
За замовчуванням вимкнено: Hub нічого не пише в «Щиро». Без перемикача доступні
лише «Перевірити зв'язок», «Лише перевірити розбіжності» та імпорт.

Що ще захищає учасниць:

- revoke іде лише тим, кого Hub сам колись увімкнув (знімок `shchyro.pushed_ids`);
  усе, що було в «Щиро» до переїзду, тік не чіпає — для цього є звірка;
- звірка без `force` зупиняється на боці «Щиро», якщо вимкнулось би понад
  `HUB_SYNC_MAX_DEACTIVATE` (50) учасниць; результат видно на сторінці ботів
  і в подіях (`shchyro.sync_blocked`);
- порожній список «Щиро» відхиляє;
- адміністраторів «Щиро» (`ADMIN_USERS`) відключити неможливо (403);
- таблиці пам'яті клієнток у «Щиро» не чіпаються: після повернення бот
  пам'ятає всю історію.

### Змінні оточення Hub (Vercel → Environment Variables)

```
SHCHYRO_API_URL=https://panel.example.com/panel-x7k2   # адреса панелі «Щиро» разом із її ADMIN_BASE_PATH
SHCHYRO_API_SECRET=<той самий рядок, що HUB_API_SECRET у bot/.env «Щиро»>
```

### Порядок переходу (етапи 2–4 ТЗ)

1. У «Щиро»: `HUB_API_SECRET` у `bot/.env`, перезібрати `mk-admin-lab`,
   зробити бекап бази.
2. У Hub: змінні вище, редеплой. Продукти → Бот «Щиро» → Доступ → **Перевірити зв'язок**.
3. **Імпортувати доступи зі «Щиро» на N днів** (типово 30): усі, хто має
   доступ у боті зараз, отримують у Hub перехідне ручне право на
   `shchyro.access`. Повторний запуск нічого не дублює. Так жодна учасниця
   не випаде, поки права з підписок не замінять перехідні.
4. Переконатись, що ресурс `shchyro.access` входить у потрібні тарифи, і за
   потреби увімкнути на ресурсі «Доступ усім активним підпискам ZenEdu».
5. **Лише перевірити розбіжності**: очікувано `вимкнулось би 0` або
   зрозумілий список.
6. Увімкнути перемикач автоматики. Далі тік і щоденна звірка працюють самі.
7. Перехідний період 1–2 тижні: панель «Доступи» у «Щиро» лишається
   аварійним резервом; записи, додані там вручну, Hub не чіпає.

### Події в картці людини

`shchyro.granted`, `shchyro.revoked`, `shchyro.error`; системні без людини:
`shchyro.sync`, `shchyro.sync_blocked`, `shchyro.import`.

### Повідомлення через бота

`shchyroNotify({ user_id, message })` у `src/lib/shchyro.ts` надсилає текст
від імені бота «Щиро» (`POST /api/v1/hub/bot/notify`). Поки не прив'язано до
автоматизацій: використовувати з коду, коли буде сценарій (нагадування про
закінчення підписки тощо).

## 2. Pull-модель (доповнення)

Якщо «Щиро» має сам питати право в Hub на кожне повідомлення:

### 2.1. Новий модуль

Скопіювати `hub_access.py` у `bot/core/hub_access.py`.

### 2.2. `bot/bot/handlers.py`

Функція `is_allowed` стає такою (Hub перший, локальний список як запасний варіант):

```python
from core import hub_access

def is_allowed(user_id: int) -> bool:
    if user_id in config.ADMIN_USERS:
        return True

    hub = hub_access.check(user_id)
    if hub is not None:
        return hub.allowed

    # Hub не відповів: стара логіка — список із панелі або .env
    if settings.MEMORY_ENABLED:
        try:
            if access.has_access_list():
                return access.is_allowed(user_id)
        except Exception as e:
            logger.error(f"Помилка перевірки списку доступу: {e}")
    if config.ADMIN_USERS:
        return user_id in config.ADMIN_USERS
    if config.ALLOWED_USERS:
        return user_id in config.ALLOWED_USERS
    return False
```

У `start_command` після успішної перевірки: `await asyncio.to_thread(hub_access.report_start, user)`.
У `handle_message` після відповіді: `await asyncio.to_thread(hub_access.report_usage, user.id)`.

### 2.3. `bot/.env`

```
HUB_API_URL=https://hub-two-ivory.vercel.app
HUB_API_KEY=<ключ із Hub → «Боти й меню» → «Зовнішні боти»>
HUB_RESOURCE=shchyro.access
```

### 2.4. Перевірка

```bash
curl -H "Authorization: Bearer $HUB_API_KEY" \
  "https://hub-two-ivory.vercel.app/api/v1/access?telegram_user_id=<ваш id>&resource=shchyro.access"
```

Очікувано `{"allowed":true,...}` для людини з підпискою і `{"allowed":false,"reason":"no_subscription",...}` без неї.
