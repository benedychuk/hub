# Запобіжники: що не чіпати без власника

Hub підключений до бази з реальними учасницями клубу (імпорт із ZenEdu). Поки власник прямо не сказав «вмикаємо», діють такі правила. Вони дублюють `CLAUDE.md`, і Claude читає їх автоматично.

## Не вмикати

1. Налаштування → Оплати → «Оплати увімкнено для учасниць» (`payments.enabled`).
2. Налаштування → Оплати → «Автоматичні запрошення на переїзд» (`payments.migrationAuto`).
3. Канали і групи → реальний канал/чат клубу → «Автоматика доступу» (`config.enforce`). Тестовий канал можна.
4. Розділ «Щиро» → автоматика доступу на бойовому боті, поки health не відповідає і не перевірено на тестовому акаунті.
5. Вебхук ZenEdu (не додавати в ZenEdu адресу Hub).

## Не робити

- Не пушити токен бота ZenEdu, ключі WayForPay, токени API в код, логи, документи. Усі секрети лише у Vercel → Environment Variables.
- Не регенерувати ключі WayForPay: їх використовує ZenEdu.
- Не ділитися посиланням на Hub-бот поза командою.
- Не розповсюджувати дані учасниць (експорти CSV, дампи, архів «Щиро»).
- Не видаляти людей, підписки, платежі, ресурси, створені не вами.
- Розсилки під час тестів: аудиторія лише «Лише мені» або фільтр за власним тегом. Ніколи «Усі».
- Не запускати імпорт із ZenEdu і дії в розділі «Міграція з ZenEdu», крім власника.

## Файли підвищеного ризику

Зміни тут погоджуються з власником до пушу: `src/lib/payments.ts`, `src/lib/wayforpay.ts`, `src/lib/telegram-access.ts`, `src/lib/access-rule.ts`, `src/lib/shchyro.ts` (частина grant/revoke), `src/app/api/payments/*`, `src/app/api/cron/*`, `drizzle/*`.

## Перед пушем у main

`npx tsc --noEmit`, `npm run lint`, `npx next build`. Нова міграція перевіряється на локальному Postgres 16 (увесь ланцюжок 0000–00NN). Змінений екран дивимось на скріншоті. Деплой у main іде автоматично, зламана збірка не падає на продакшен (Vercel лишає попередню версію), але блокує наступні.

## Якщо щось пішло не так

Vercel → Deployments → попередня версія → Promote. Повідомити власника.
