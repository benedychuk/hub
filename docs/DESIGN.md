# Hub · правила дизайну інтерфейсу

Це обов’язковий стандарт для всіх екранів Hub. Кожна нова сторінка або зміна UI перевіряється за чеклістом у кінці. Орієнтири: Linear, Stripe Dashboard, Vercel, Shopify Polaris, Atlassian Design System, евристики Nielsen, Refactoring UI.

## 1. Принципи

1. **Одна головна дія на екран.** Помаранчева кнопка `btn pri` лише одна на видимій області. Решта: `btn` (вторинні) або `btn ghost` (третинні). Деструктивні дії ховаються в меню ⋮ і завжди з підтвердженням.
2. **Спочатку зрозуміло, потім гарно.** Кожен блок має заголовок, який каже, що тут робити; кожне поле має підпис і, за потреби, короткий помічний текст під ним. Ніяких технічних термінів у підписах (не `chat_id`, а «ID чату» з поясненням, де його взяти).
3. **Прогресивне розкриття.** Складні налаштування згорнуті у групи (`FilterGroup`, `details`); на першому екрані лише те, що потрібно 80 % випадків. Просунуте відкривається за кліком.
4. **Стан завжди видимий.** Після дії користувач бачить результат: зелений `alert ok`, оновлений лічильник, змінений статус. Довгі процеси показують прогрес і що робити далі.
5. **Порожній стан веде до дії.** Порожня таблиця або список показує одне речення «що це» і кнопку «створити перший».
6. **Симетрія й сітка.** Усі відступи з шкали 4 / 8 / 12 / 16 / 24 / 32 px. Сусідні поля в рядку мають однакову висоту підписів (помічний текст тільки під полем, не в підписі). Колонки форм 1:1 або 2:1, не довільні.
7. **Не вигадувати стилі на місці.** Жодних `style={{…}}` для кольорів, тіней, радіусів, розмірів шрифту. Лише токени й класи з `globals.css` або компоненти з `src/components/ui`. Інлайн-стилі допустимі тільки для динамічних значень (ширина прогресу, фонове зображення).

## 2. Токени

| Що | Значення |
|---|---|
| Акцент (дія, активний стан) | `--orange` #EE6C29, градієнт на `btn pri` і активному пункті меню |
| Текст | `--ink` #282B2B, вторинний `--ink-2`, підказки `--ink-3` |
| Фон сторінки | білий, картки білі з `--line` рамкою і `--shadow-sm` |
| Допоміжний | `--moon` #7AA6B3 для інформаційних станів, посилань |
| Семантика | `--good` успіх, `--warn` увага, `--crit` помилка/деструктивне, кожен має `-soft` фон |
| Радіуси | 8 px дрібні елементи, 10 px поля й кнопки, 12 px картки, 16 px модальні вікна |
| Шрифти | Unbounded лише для заголовків сторінок і великих чисел; IBM Plex Sans для тексту; IBM Plex Mono для id, дат, кодів |
| Розміри тексту | 11 px мітки таблиць, 12.5 px помічний текст, 13.5 px основний, 14.5 px текст у редакторі, 16–18 px заголовки |
| Висота контролів | 36 px (`btn`, `input`, `select`), 30 px `btn sm` |

Темний колір `--jet` використовується лише для бічної панелі. У робочій області темних плашок немає.

## 3. Компоненти (`src/components/ui`)

- `PageHeader` — назва, статус, дії; кнопка «← Назад» зліва.
- `Stepper` — кроки майстра «1 Зміст › 2 Отримувачі › 3 Надсилання»; пройдені кроки клікабельні.
- `Section` — картка з заголовком і описом; вміст у `form` сітці.
- `Field` — підпис + контрол + помічний текст/помилка; `FormRow cols=2` для пар полів однакової ширини.
- `Checkbox`, `Switch`, `Segmented`, `RadioCards` — на Radix, доступні з клавіатури. Switch для «увімкнено/вимкнено» налаштувань, Checkbox для множинного вибору у фільтрах, RadioCards для вибору одного з 2–4 варіантів із поясненням.
- `Kebab` + пункти — меню ⋮ на Radix DropdownMenu; іконки lucide; деструктивні пункти червоні й останні, після роздільника.
- `Modal` — діалог із заголовком, хрестиком, кнопками внизу праворуч (вторинна зліва від головної).
- `Stat` — велика цифра з підписом і поясненням; `EmptyState` — порожній стан із дією; `Alert` — ok / warn / bad.
- `RichText` — єдиний текстовий редактор для повідомлень.
- Іконки: тільки `lucide-react` розміром 16 px у кнопках і 18 px у навігації. Емодзі в інтерфейсі не використовуються (лише в тексті, який пише користувач).

## 4. Патерни екранів

**Список (воронки, розсилки, канали).** Тулбар: пошук зліва, фільтри/сортування поруч, головна дія праворуч. Нижче сітка карток або таблиця. У таблиці числа вирівняні праворуч моноширинним, статуси як `pill`, дії у ⋮ в останній колонці.

**Майстер (розсилка, підключення чату).** Stepper угорі. Дві колонки 2:1: зліва зміст кроку, праворуч підсумок або налаштування, що не міняються. Внизу лівої колонки одна головна кнопка «Далі» і вторинні «Зберегти чернетку». Кожен крок можна зберегти й повернутись.

**Редактор об’єкта (крок воронки, ресурс).** Заголовок із назвою і статусом, вкладки, форма 2:1, кнопки збереження закріплені в правій колонці.

**Фільтри аудиторії.** Спершу три великі варіанти (усі / за фільтрами / лише мені), потім згорнуті групи фільтрів із лічильником активних умов у заголовку групи. Праворуч завжди видимий результат: «Отримають N» і приклад списку.

## 5. Тексти

- Підписи полів короткі, з великої літери, без крапки. Помічний текст одним реченням під полем.
- Кнопки називають результат: «Надіслати зараз», «Запланувати на 10 вересня, 10:00», «Створити посилання», а не «ОК» чи «Підтвердити».
- Повідомлення про помилку каже, що сталось і що зробити.
- Числа у прозі не пишемо; лічильники в `Stat` або `pill`.

## 6. Чекліст перед пушем UI

- [ ] Одна `btn pri` у видимій області; деструктивне в ⋮ з підтвердженням.
- [ ] Усі поля в `Field`, пари полів у `FormRow`, підписи однієї висоти, помічний текст під полем.
- [ ] Немає інлайн-стилів для кольорів, розмірів, тіней. Немає емодзі в UI.
- [ ] Порожній стан із дією; після кожної дії видно результат.
- [ ] Заголовок сторінки, хлібні крихти «← Назад», вкладки або stepper, як у патерні.
- [ ] Перевірено на ширині 1280 і 1536 px; довгі назви не ламають сітку (ellipsis).
- [ ] Знімок екрана переглянуто перед пушем (локальний `next start` + headless Chrome).
