# План переїзду з ZenEdu

Мета: перевести учасниць у Hub, не втративши жодної підписки, зберігши наявний бот клубу. Переїзд іде трьома незалежними шарами. Статус кожного кроку оновлюється тут.

## Шар 1. Бот

Бот у Telegram визначається токеном. Зараз токен у ZenEdu.

1. [ ] Hub: дія «перенести співрозмовників» на сторінці Боти й меню: для всіх людей із `telegram_user_id` (крім `zenIsBlocked`) створити `identities` з `bot_key = hub`, `chat_id = telegram_user_id` (для приватного чату вони збігаються). Після цього Hub може писати їм без повторного /start.
2. [ ] Hub: дія «перемкнути бот»: встановити вебхук і команди для токена з `TELEGRAM_BOT_TOKEN`.
3. [ ] Власник: BotFather → Revoke token для бота клубу → новий токен у Vercel `TELEGRAM_BOT_TOKEN` → Redeploy → натиснути «перемкнути бот».
4. Наслідки: ZenEdu втрачає воронки, розсилки, повідомлення з бота, керування каналом. Списання в ZenEdu продовжуються (вони не залежать від бота). Імпорт через ZenEdu API далі працює.

## Шар 2. Канал

До перемикання бота Hub має сам впускати й виключати, інакше після відкликання токена каналом ніхто не керує.

1. [ ] Hub: `syncEntitlementsFromSubscriptions` дає право на канал і за активними підписками ZenEdu, якщо в ресурсу `zenedu_grants = true` (зараз лише за Hub-підписками; без цього автоматика виключила б чинних учасниць). Те саме правило грейсу 24 год.
2. [ ] Hub: імпорт підписок із ZenEdu щогодини (зараз щодня о 04:00 і вручну).
3. [ ] Власник: на реальному каналі увімкнути `zenedu_grants`, потім «Автоматику доступу»; добу спостерігати на сторінці каналу, що список «виключити» порожній.

## Шар 3. Гроші

Автосписання тримається на токені картки у WayForPay. Мерчант спільний, але токенами володіє ZenEdu.

Варіант А (перевірити першим): кабінет WayForPay → «Регулярні платежі». Якщо там є активні графіки, ZenEdu створював їх на боці WayForPay, і Hub може перебрати їх за orderReference першої оплати через `WFP_REGULAR_PASSWORD`. Людині нічого робити не треба. Статус: [ ] власник перевіряє.

Варіант Б (готовий у коді, вимкнений): за N днів до списання Hub пише людині в бот, перевірочний платіж 1 грн повертається, Hub копіює ціну й дату списання з ZenEdu. Після привʼязки власник скасовує підписку в ZenEdu з чек-листа на сторінці «Міграція» (інакше подвійне списання). Хто не привʼязав, лишається в ZenEdu ще цикл. Перемикач: Налаштування → Оплати → «Автоматичні запрошення на переїзд», днів до списання `payments.migrationDays`.

## Порядок

1. Доробити шар 2 п.1–2 і шар 1 п.1–2 (код). Перевірити на тестовому каналі з тестовим ботом.
2. Шар 2 п.3: автоматика на реальному каналі, доба спостереження.
3. Шар 1 п.3: відкликати токен, перемкнути бот.
4. Шар 3: варіант А або Б, два-три місячні цикли.
5. Коли в ZenEdu не лишається активних підписок, вимкнути ZenEdu.

## Що лишається після переїзду

Імпорт із ZenEdu можна вимкнути; таблиці `offers` (ZenEdu) і замовлення з `source = zenedu` лишаються як історія для звітів.
